01Variables and data types

Student variables, primitive vs. reference values, a template literal.

notes

let can be reassigned; const cannot be reassigned (though object/array contents it points to can still change). typeof null famously returns "object" — a long-standing language bug kept for backward compatibility. The primitive types are string, number, boolean, null, undefined, bigint and symbol; everything else (objects, arrays, functions) is a reference type.

02Arrays

map, filter, find, reduce and includes over [3, 7, 2, 10, 5], without mutating the source.

notes

map, filter and reduce all return a new array or value and leave the original untouched — that's what makes them chain-friendly. find stops at the first match instead of scanning the whole array, so it's cheaper than filtering and reading index 0.

03Arrays of objects

Four students, filtered, mapped and reduced without mutating the source objects.

notes

Building the "passed" list with students.map(s => ({...s, passed: s.grade >= 70})) keeps the original array of objects intact — spreading each student into a new object avoids mutating them, which matters once other code elsewhere still holds a reference to the originals.

04Objects

Reading, updating, adding, removing, and destructuring (including nested and renamed).

notes

Renaming during destructuring — const { name: userName } = user — is handy when a field's generic name (name, id, value) would shadow something else in scope. Nested destructuring, { address: { city } }, only works if address is guaranteed to exist; otherwise it throws.

05Values and references

Why copy = original shares state, and how spread copies shallowly.

notes

Assigning an object copies the reference, not the data — original and copy point at the same memory, so mutating one mutates both. Spread ({...original}) makes a new top-level object, which is enough for flat data but not for nested objects: the nested address object is still shared between the copy and the original after a shallow spread, so changing copy.address.city changes it everywhere unless the nested object is spread too, e.g. {...user, address: {...user.address}}.

06Functions

Five small functions, one written both as a function declaration and as an arrow function.

notes

Function declarations are hoisted and get their own this; arrow functions aren't hoisted the same way and inherit this from the enclosing scope. For short, stateless helpers like these the two are interchangeable — the difference matters more inside classes or callbacks.

07Functions as values

Passing add and multiply into a calculate function.

notes

Yes to both: functions can be stored in variables and passed around like any other value — that's what "first-class functions" means. add refers to the function itself (you can pass it, print it, store it); add() calls it immediately and evaluates to its return value.

08Scope

The same identifier shadowed at global, function and block level; var vs let/const.

notes

Each inner message shadows the outer one only within its own block — the global variable is never overwritten. var is function-scoped, so a var declared inside an if block leaks out to the whole function; let and const are block-scoped and stay trapped inside the { } they were declared in.

09Closures

createCounter and createAdder, each keeping their own private state.

notes

The inner function keeps a live reference to the outer function's variables even after the outer function has finished running — that reference is the closure. Each call to createCounter() creates a fresh count variable, so two counters never interfere with each other, which is what lets addFive called again keep remembering value = 5.

10Destructuring, spread and rest

Pulling values out, combining arrays, and a variadic sum(...numbers).

notes

Spread and rest use the same ... syntax but do opposite jobs: spread expands a collection into individual elements ([...a, ...b]), while rest gathers separate arguments back into a single array (function sum(...numbers)). Which one is happening depends entirely on the position — inside a literal it's spread, inside a parameter list it's rest.

11Optional chaining and default values

Safely reading user.address.city when address might not exist, and comparing || vs ??.

notes

Accessing .city directly on a missing address throws; ?. short-circuits to undefined instead of throwing, and ?? "City not specified" only kicks in for null/undefined. That's the key difference from ||: || also treats 0, "" and false as "missing" and falls back, which is wrong whenever those are legitimate values — ?? only cares about null/undefined.
